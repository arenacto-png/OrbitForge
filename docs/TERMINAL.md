# Workspace terminal

OrbitForge currently provides a limited Kotlin-based workspace command runner. It does not start `/system/bin/sh` and does not execute arbitrary shell syntax. Supported commands are `help`, `pwd`, `ls`, `find`, `cat`, `head`, `grep`, `wc`, `mkdir`, `touch`, `echo`, and `clear`.

Every filesystem path is resolved inside the app-private workspace. Agent-facing `ls` and `find` omit common sensitive paths and canonical aliases to sensitive or out-of-workspace targets; `find` additionally limits traversal to 1,000 entries, results to 200 paths, and output to 20,000 characters. A stateful tokenizer supports single- and double-quoted arguments (including spaces) and rejects unmatched quotes, multiline input, backslash escape syntax, and shell control operators outside quotes. Operator characters inside quoted arguments are plain text. No shell expansion, command substitution, pipelines, redirection, chaining, or system shell is invoked. This is a safe starter terminal, not a full Linux environment. A future runtime adapter can connect an explicitly configured Termux or remote executor with separate permissions. `grep` reads through the same agent-safe policy as `cat`/`head`/`wc`: sensitive paths and secret-like file contents are rejected. Its result is limited to 100 matches and 20,000 characters; blank search terms are rejected. `mkdir` and `touch` require user approval and also reject sensitive names (for example `.ssh` and `.env`) plus canonical symlink aliases to sensitive or out-of-workspace targets before creating directories or files.
